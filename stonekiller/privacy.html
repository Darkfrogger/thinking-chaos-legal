Draft privacy policy

This draft describes StoneKiller 0.30.0. It is not yet the final privacy policy for the app's release.

The release version, permissions, third-party services, Android backups and intended age groups still need confirmation. The arrangements for student data, school servers, consent, security, retention and deletion are also being finalised.

StoneKiller is a drum practice and teaching application developed and published by Patrick Reeb, an individual developer. This policy describes local data, device permissions, optional class connections, online media and files you choose to share. Features vary by edition, platform and version.

1. Data stored on your device

StoneKiller uses local app or browser storage for lessons, grooves, lists, practice plans, progress and self-assessments, settings, song studies, class journals, saved recordings and imported content. A StoneKiller online account is not required for local practice.

Teaching features can also store a student register, including names and aliases, student and parent contact details, billing or address information entered in notes, goals, lesson notes, history, attendance, schedules and attachments. These records may contain information about other people. Teachers should enter only what is needed and manage their use and retention appropriately.

Local storage does not mean that every feature is offline. Class connections, online media and sharing can send data off the device, as described below.

2. Microphone, camera, files and nearby devices

  • Microphone: recording and rhythm analysis features can access audio you choose to capture. Recordings or derived practice data can be kept locally when saved. Audio/video class features may also use the microphone.
  • Camera: QR scanning, camera and video practice tools, short demonstrations and supported class video features can access images or video. Some features display a live view; others let you save or send a recording.
  • Files: import, export, backup and restore features read or write files you select, such as exercises, song media, recordings and student records.
  • Other inputs: supported tools can read MIDI notes from a connected instrument or request screen/tab audio for tempo analysis when you choose that input.
  • Local network and nearby-device permissions: class discovery, connections and supported Android lesson Wi-Fi features use the device's networking facilities. Older Android versions may request a location permission for Wi-Fi functions; the exact permissions in the release build still need verification.

You can manage camera and microphone access in your device or browser settings. Refusing a permission can prevent the related feature from working.

3. Classes and connections to other devices

Joining or hosting a class exchanges information with the teacher, participating devices and, where configured, a school relay. This can include a display name, participant or device identifiers, public identity keys used for teacher linking, exercises, tempo and playback state, messages, homework, participation and exercise feedback. The app uses a randomly generated installation identifier, which can also be included in backups. Optional camera and demonstration features can transmit images, video or audio between devices. Connected camera tools can also send a device name, preview image and recording status, including battery or available storage information where supported.

By default, classes use a local-network connection. A school server uses the address configured by the user or school; its operator and deployment determine where that traffic goes. A class connection transfers data between devices even when no public internet service is involved.

Class journals, homework and received demonstrations may remain on the teacher's and students' devices after the connection ends. A relay forwards class messages during a class. If your school operates a server, ask it how connection logs and other server data are handled and how long they are kept.

The app's general class traffic must not be assumed to be end-to-end encrypted. Shared relay traffic can reach other participants in the same class room, including messages or demonstrations marked for a particular recipient; selecting a recipient is not a guarantee of confidential delivery. Use a trusted network. A teacher or school must confirm who is responsible for student data, what participants can see, any required consent and the server operator's security and retention arrangements before deploying these features.

4. Optional online media and external services

Song studies support links to YouTube, Vimeo and SoundCloud. Pasting a supported link can request its title or other metadata from that provider before playback. The request includes the media address; the provider also receives the connection information needed to answer it, such as an IP address. Using a direct online media URL also contacts the server hosting that file, including for supported media analysis.

Loading an online player or enabling the setting to load a provider automatically connects to that provider's player and related resources. The provider can then process technical information and use cookies or similar technologies according to its own practices, your browser and your account settings. Playback consent does not prevent the earlier metadata request.

Review the relevant provider's policy: Google / YouTube, Vimeo, and SoundCloud. Use local media and avoid online links if you do not want to trigger these provider connections.

5. Backups, exports and sharing

You can export content and create a full backup to move data to another device. Depending on the export, files can contain practice history, recordings, class journals or student information. Store them somewhere appropriate for their contents.

When you choose a messaging app, email app, cloud folder or another sharing destination, the selected service and recipients receive the content you send. Their processing and retention are governed by their own arrangements. Deleting an item in StoneKiller does not remove copies already exported or received by someone else.

Device and operating-system backups vary by platform. Android system-backup and restore settings still need confirmation. Exported backups are not guaranteed to be encrypted.

6. Retention, deletion and your choices

Saved local data generally stays until it is removed through the relevant app controls, the app or browser's storage is cleared, or the platform removes it. Transcription history automatically keeps only the latest 40 takes. Uninstalling may remove app data, but does not establish that separate exports, backups or copies on other devices have been deleted.

  • Use the available delete controls for saved content, recordings, student records and class journals. Archiving a student retains their records; use Delete to remove them. Deleting a journal class also removes its stored demonstration videos from that journal.
  • In Settings → My classes, turn off keeping class content in the journal on a shared device, and remove teacher links you no longer need. Turning off future journal saving is not a promise to erase earlier entries.
  • Remove backup and export files separately from their storage locations. Ask recipients or a school operator about copies they hold.
  • To clear app-managed storage, use your device or browser's app-data controls. Save anything you want to keep first. Separately saved recordings, project folders and original media can remain outside that storage and must be managed individually. Backup restoration may bring back previously saved data.

Retention periods and the handling of privacy requests, school-hosted data and support communications are still being finalised.

7. Security and children

Protect devices and backups with appropriate access controls, review what is shared and use networks you trust. This policy does not promise that all local data, backups or class traffic is encrypted.

StoneKiller includes teacher and student features. Its intended age groups and the notices and consent arrangements for children, parents, teachers and schools still need confirmation.

8. Visiting this policy website

This page is hosted on GitHub Pages. Its published HTML includes no analytics script, external font, embedded player or form. GitHub states that it logs and stores visitors' IP addresses for security when a GitHub Pages site is visited. See the GitHub Privacy Statement for GitHub's processing and retention practices.

Following an external link connects you to that website. Visiting this policy page is separate from using StoneKiller's local practice features.
